## What actually shipped

This week I stopped treating `~/.claude` as throwaway local state and turned it
into a versioned repo. The whole point: my Claude Code setup — permissions,
hooks, slash commands, rules, skills, and plugin manifests — is now reproducible
across machines and has a history I can read back.

The commit trail tells the story. It opens on **2026-05-29** with the `init`
commit (skills, hooks, rules, and the `sync.sh` helper) and a docs pass that
added a comprehensive README and a repo-level `CLAUDE.md`. On **2026-05-30** I
moved the find-skills trigger off session-start and onto the third turn of each
session, synced the plugin manifests, and landed a config-maintenance commit
that pruned stale turn-counters, allowlisted the context-mode MCP tools, and
wrote down a tool-preferences rule. That last commit became **v1.0.1**.

```
2026-05-29  init: skills, hooks, rules, sync script
2026-05-29  docs: comprehensive README + repo-level CLAUDE.md
2026-05-30  hooks: find-skills trigger on 3rd turn (not session start)
2026-05-30  chore: sync plugin manifests
2026-05-30  config: prune turn-counters · allowlist context-mode MCP · tool prefs  ── v1.0.1
```

![Scroll capture of the Claude Code Config project page on arkashj.com, recorded with playwright-cli and stitched into a GIF with gifski](/assets/projects/claude-code-config.gif)

The trick that makes this safe is the whitelist `.gitignore`: ignore everything
at the top level, then re-include only the hand-authored config. Secrets,
transcripts, downloaded plugin code, and machine-specific local settings never
enter git by construction — I don't have to remember to exclude them.
