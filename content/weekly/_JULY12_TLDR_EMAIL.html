Memory is the bottleneck now

For founders, investors, and leaders: the GPU is not the whole AI story. Every AI product still has to move, hold, and retrieve a lot of data. That is why memory is becoming a real business constraint—not just a chip detail.

Headlines & launches

SK Hynix raises $26.5B in its U.S. ADR debut; shares close up 12.8% [Bloomberg]

SK Hynix sold 177.9M ADRs at $149, raised $26.5B, opened at $170, and closed at $168.01. Situational Awareness, Coatue, and Baillie Gifford indicated interest in up to $7B of the deal.

  • The money is going into fab capacity, advanced packaging, and EUV equipment.
  • The story is simple: the market is funding more memory supply because AI demand is still eating through the existing supply.
  • The more interesting question is how quickly that new supply arrives and changes the cycle.

Samsung’s memory business is now producing Nvidia-sized profit numbers [Bloomberg]

Samsung’s preliminary second-quarter operating profit came in at $58.5B, above Nvidia’s most recent quarterly operating profit of $53.54B. The memory business is no longer a side character in the AI buildout.

  • DRAM, NAND, HBM, and enterprise SSD pricing are all part of the same supply story.
  • SK Hynix, Samsung, and Micron are the tight side of that story; they are all building more capacity into it.

What this means

  • Founders: AI product costs are not only about the model API. The more your product remembers, searches, and automates, the more the surrounding data stack matters. Build for a useful workflow, not just a good demo.
  • Investors: Follow the full buildout, not only the GPU. Memory, storage, packaging, power, and cooling are all places where AI spending lands.
  • Leaders: Treat AI as an operating-system change. Start with the work you want to automate, then budget for the data, context, and governance needed to run it reliably.

Why NAND matters [Bloomberg]

Agents do not only generate tokens. They read repos, open PDFs, store tool output, cache models, write logs, keep checkpoints, and come back to work later. That is a storage problem as much as a compute problem.

  • HBM is the GPU’s close-in workspace. It is very fast and very expensive. Without enough bandwidth, the GPU waits.
  • DRAM is the broader working memory. It holds active data across servers, PCs, and phones.
  • NAND is persistent storage. It is the flash in SSDs: slower than HBM, but it keeps the repos, documents, weights, caches, checkpoints, and agent traces.
  • You need all three. HBM makes an inference system fast; DRAM keeps the machine working; NAND keeps the work when the session ends.

Developer workflow

Maximize ROI on $400

One Claude Code account plus one Codex account is about $400/month. This workflow is producing around 2K commits a month when planning, execution, review, and context are treated as separate jobs.

  • Plan in Fable medium. Start with business criteria, acceptance criteria, risks, and todos. Do not use high for planning by default; it is a token killer.
  • Make the GitHub ticket real. Use `/goal` commands and give each task a clear done state before execution starts.
  • Terra high for normal execution; Sol high for hard work. Spend the expensive pass on tasks that are actually difficult.
  • Run 5–10 narrow PRs, then review them. A generated diff is not a reviewed change.
  • Update context. Keep `CLAUDE.md`, `context.md`, and component files current so the next agent starts informed.
