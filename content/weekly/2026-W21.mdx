## What actually shipped

Tooling week. Four additions to the dev pipeline and one set of content backfills.

The big one: **the client-state layer got real**. `lib/store.ts` is a small
Zustand store carrying the command palette open/close, the mobile-nav open
state, and a generic modal slot for future cross-component coordination.
`Nav` and `CommandPalette` were both reading/writing the same logical state
through props before — now they share it through the store and the Cmd+K
keyboard handler lives next to its state. The admin weekly form is the
first **TanStack Query** consumer: `useMutation` wraps the
`addWeeklyItem` server action with automatic `isPending`/`isError`/data
tracking and a reset-on-success flow.

**Biome** is in alongside ESLint + Prettier — not replacing them.
Formatting stays with Prettier; Biome runs read-only lint over the
app/components/lib trees and immediately caught 11 things ESLint missed
(button-type, ARIA-on-disallowed-elements, useless regex escapes,
suspicious JSX semicolons). Six of those are pre-existing and queued for
a follow-up.

**Knip** got configured + ran + cleaned. The cleanup pass removed 14
files / 2 deps / 8 exports — 977 deletions in total: `lib/finance.ts`,
`lib/highlights.ts`, `lib/learnings.ts`, every `components/embeds/*`
(Tweet/YouTube/Substack/LinkedInPost/Gist — none referenced from MDX),
the legacy `CommitsSidebar`/`ExperienceStoryNode`/`ThesisTracker`/`TradeLog`
sections, plus `react-tweet` and `rehype-slug` deps that nothing imported.
Each deletion verified by grep across `content/`, `app/`, `components/`,
`lib/`.

The **architecture map** picked up an eighth diagram — `ClientStateDiagram`
shows the provider chain (html → ClerkProvider → Providers/QueryClient →
ThemeProvider → app surface) next to the Zustand slices and their
consumers. The existing `ComponentTreeDiagram` got refreshed to show the
full provider stack instead of the old Clerk-only chain.

## Reading

The recovery from the parallel-agent worktree escape was the lesson of
the week. Four agents dispatched in `isolation: "worktree"` mode against
the same base branch — one of them somehow ended up modifying the main
tree instead of its isolated copy, broke a dynamic-import refactor on
`WeeklyGrid.tsx`, and left ~25 uncommitted files behind. The recovery
path: stop the running agent, stash the dirty changes, drop the stash,
cherry-pick the clean worktree branch (Biome) onto the working branch,
and discard the half-refactor. Cost: about ten minutes. Bias for next
time: verify a worktree branch is alive _before_ assuming the agent
operated in isolation, and don't dispatch parallel agents that touch the
same root files without rebase contracts.
